Renaming elements and types ​

Element and type names in a schema become field and type names in Julia. A schema can use names that are not valid Julia identifiers, such as single-record, or names that clash with something in Julia. The mapping keyword of the generator gives them other names in Julia, while documents keep the names the schema defines.

The mapping ​

mapping takes one of two forms:

  • A flat dictionary, "schema name" => "Julia name", renames element names and type names alike.

  • A dictionary with the keys "Fields" and "Types", each a dictionary of renames, renames elements and types separately. Either key may be left out.

julia
# flat: the same renames for elements and types
mapping = Dict("single-record" => "single_record", "record-type" => "RecordType")

# separate
mapping = Dict(
    "Fields" => Dict("single-record" => "single_record"),
    "Types" => Dict("record-type" => "RecordType"),
)

A mapping with "Fields" or "Types" may hold no other keys. The schema's own name, which names the generated module, cannot be renamed. Names that are not in the mapping are used as they are.

An example ​

This schema uses hyphens in its element names and in the name of a type:

julia
print(read(joinpath(examples, "records.xsd"), String))
<?xml version="1.0"?>
<schema xmlns="http://www.w3.org/2001/XMLSchema" xmlns:TestRenamedElements="TestRenamedElements" targetNamespace="TestRenamedElements">

<element name="document" type="TestRenamedElements:documentType"/>

<complexType name="record-type">
    <annotation>
        <documentation>A complex type whose name and element names are not Julia identifiers.</documentation>
    </annotation>
    <sequence>
        <element name="Element-string" type="string"/>
        <element name="Element-double" type="double"/>
    </sequence>
</complexType>

<complexType name="documentType">
    <sequence>
        <element name="single-record" type="TestRenamedElements:record-type"/>
        <element name="repeated-record" type="TestRenamedElements:record-type" maxOccurs="unbounded"/>
        <element name="plain" type="string"/>
    </sequence>
</complexType>

</schema>

Generated as it is, the module defines fields such as single-record, which Julia cannot parse; including it fails. With a mapping, every name becomes an identifier:

julia
mapping = Dict(
    "Fields" => Dict(
        "single-record" => "single_record",
        "repeated-record" => "repeated_record",
        "Element-string" => "element_string",
        "Element-double" => "element_double",
    ),
    "Types" => Dict("record-type" => "RecordType"),
)
module_file = xsd_to_struct_module(joinpath(examples, "records.xsd"), output_dir; mapping)
include(module_file)
using .TestRenamedElements
fieldnames(documentType)
(:single_record, :repeated_record, :plain, :__xml_attributes, :__validated)

The element renames are stored in the module:

julia
TestRenamedElements.__meta.XSDMapping
Dict{String, String} with 4 entries:
  "Element-double"  => "element_double"
  "Element-string"  => "element_string"
  "repeated-record" => "repeated_record"
  "single-record"   => "single_record"

Loading and writing ​

The loader reads each element into the field it was renamed to:

julia
records = load(joinpath(examples, "records.xml"), TestRenamedElements)
(records.single_record.element_string, [r.element_double for r in records.repeated_record])
("one", [2.5, 3.5])

The writer writes each field under the element name from the schema, so the document comes back with the schema's names:

julia
copy_path = joinpath(output_dir, "records_copy.xml")
write_xml(records, copy_path)
print(read(copy_path, String))
<?xml version="1.0" encoding="utf-8"?>
<TestRenamedElements:document xmlns:TestRenamedElements="TestRenamedElements" xsi:schemaLocation="TestRenamedElements records.xsd" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <single-record>
    <Element-string>one</Element-string>
    <Element-double>1.5</Element-double>
  </single-record>
  <repeated-record>
    <Element-string>two</Element-string>
    <Element-double>2.5</Element-double>
  </repeated-record>
  <repeated-record>
    <Element-string>three</Element-string>
    <Element-double>3.5</Element-double>
  </repeated-record>
  <plain>text</plain>
</TestRenamedElements:document>

Where renames apply ​

Name in the schemaRenamed byNotes
element"Fields"Also renames the member of a choice.
complex or simple type"Types"The type keeps its submodule and its choice fields consistent with the new name.
built-in type such as double—Always the same Julia type, even when a schema type of the Julia type's name is renamed.
schema (module) name—Raises an ArgumentError.
the value field of a simple type—Always value.

generate_modules takes the same mapping and applies it to every module it generates.
