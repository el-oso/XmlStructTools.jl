Getting started ​

This page goes once through the whole cycle: generate a module from a schema, load a document, change it, and write it back.

Installation ​

XsdToStruct, XmlStructLoader, XmlStructWriter and AbstractXsdTypes are in the General registry. XmlStructPugixml, which the loader parses documents with, is not, so it is added from the repository first:

julia
using Pkg
Pkg.add(url = "https://github.com/Tom-Lemmens/XmlStructTools.jl", subdir = "XmlStructPugixml.jl")
Pkg.add(["XsdToStruct", "XmlStructLoader", "XmlStructWriter"])

A generated module needs AbstractXsdTypes and Reexport, and Dates and TimeZones when the schema has date or time types. They have to be in the environment where the module is used:

julia
Pkg.add(["AbstractXsdTypes", "Reexport", "Dates", "TimeZones"])

The docstring at the top of each generated module lists the packages it needs.

The workflow ​

A schema ​

The examples in this documentation use a small schema for customer orders. An order has an id, the time it was placed, either an email address or a phone number, and one or more order lines. A product code must have the form ABC-1234, and a quantity must be at least 1.

julia
print(read(joinpath(examples, "orders.xsd"), String))
<?xml version="1.0"?>
<schema xmlns="http://www.w3.org/2001/XMLSchema" xmlns:Orders="Orders" targetNamespace="Orders">

    <element name="orders" type="Orders:OrdersType"/>

    <simpleType name="Sku">
        <annotation>
            <documentation>A product code: three capital letters, a dash and four digits.</documentation>
        </annotation>
        <restriction base="string">
            <pattern value="[A-Z]{3}-[0-9]{4}"/>
        </restriction>
    </simpleType>

    <simpleType name="Quantity">
        <restriction base="integer">
            <minInclusive value="1"/>
        </restriction>
    </simpleType>

    <complexType name="Line">
        <annotation>
            <documentation>One product in an order.</documentation>
        </annotation>
        <sequence>
            <element name="sku" type="Orders:Sku"/>
            <element name="quantity" type="Orders:Quantity"/>
            <element name="price" type="decimal"/>
            <element name="note" type="string" minOccurs="0"/>
        </sequence>
    </complexType>

    <complexType name="Order">
        <sequence>
            <element name="id" type="string"/>
            <element name="placed" type="dateTime"/>
            <choice>
                <element name="email" type="string"/>
                <element name="phone" type="string"/>
            </choice>
            <element name="line" type="Orders:Line" maxOccurs="unbounded"/>
        </sequence>
    </complexType>

    <complexType name="OrdersType">
        <sequence>
            <element name="order" type="Orders:Order" maxOccurs="unbounded"/>
        </sequence>
    </complexType>

</schema>

Generating the module ​

xsd_to_struct_module reads the schema and writes a module into a directory of the same name under the output directory. It returns the path of the file to include:

julia
module_file = xsd_to_struct_module(joinpath(examples, "orders.xsd"), output_dir)
basename(module_file)
"orders.jl"

The module takes the name of the schema's target namespace, here Orders. It exports one type per schema type, and re-exports Dates and TimeZones, whose types the fields use:

julia
include(module_file)
using .Orders
schema_types = filter(names(Orders)) do name
    value = getglobal(Orders, name)
    value isa DataType && parentmodule(value) === Orders.Orders_struct
end
5-element Vector{Symbol}:
 :Line
 :Order
 :OrdersType
 :Quantity
 :Sku

Loading a document ​

julia
print(read(joinpath(examples, "orders.xml"), String))
<?xml version="1.0" encoding="utf-8"?>
<Orders:orders xmlns:Orders="Orders" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="Orders orders.xsd">
    <order>
        <id>A-1001</id>
        <placed>2026-03-02T09:15:00</placed>
        <email>ada@example.com</email>
        <line>
            <sku>KBD-0042</sku>
            <quantity>2</quantity>
            <price>49.90</price>
        </line>
        <line>
            <sku>MSE-0007</sku>
            <quantity>1</quantity>
            <price>19.50</price>
            <note>gift wrap</note>
        </line>
    </order>
    <order>
        <id>A-1002</id>
        <placed>2026-03-02T11:40:00+01:00</placed>
        <phone>+31 40 123 4567</phone>
        <line>
            <sku>MON-0100</sku>
            <quantity>1</quantity>
            <price>229.00</price>
        </line>
    </order>
</Orders:orders>

load reads the document into the type of the schema's root element:

julia
orders = load(joinpath(examples, "orders.xml"), Orders)
typeof(orders)
Main.Orders.Orders_struct.OrdersType

Elements are fields, repeated elements are vectors, and an element left out is nothing:

julia
first_order = orders.order[1]
(first_order.id, first_order.placed, length(first_order.line), first_order.line[1].note)
("A-1001", DateTimeNs(Dates.DateTime("2026-03-02T09:15:00"), 0), 2, nothing)

The members of a choice are read like fields; the one that is absent is nothing:

julia
(orders.order[1].email, orders.order[2].phone, orders.order[2].email)
("ada@example.com", "+31 40 123 4567", nothing)

A date and time becomes a DateTimeNs, which keeps the digits below a millisecond. It wraps a ZonedDateTime when the text has a zone offset and a DateTime when it does not:

julia
(orders.order[1].placed, orders.order[2].placed)
(DateTimeNs(Dates.DateTime("2026-03-02T09:15:00"), 0), DateTimeNs(TimeZones.ZonedDateTime(2026, 3, 2, 11, 40, tz"UTC+01:00"), 0))

Changing and writing it back ​

The generated structs are immutable, so a change builds a new object. The constructors take keyword arguments named after the elements, and check the schema's restrictions:

julia
extra_line = Line(sku = Sku("CBL-0003"), quantity = Quantity(3), price = 4.5)
changed = Order(
    id = first_order.id,
    placed = first_order.placed,
    email = first_order.email,
    line = [first_order.line; extra_line],
)
updated = OrdersType(order = [changed, orders.order[2]], __xml_attributes = orders.__xml_attributes)

write_xml writes the object as a document:

julia
copy_path = joinpath(output_dir, "orders_copy.xml")
write_xml(updated, copy_path)
print(read(copy_path, String))
<?xml version="1.0" encoding="utf-8"?>

    <placed>2026-03-02T09:15:00</placed>

      <sku>KBD-0042</sku>
      <quantity>2</quantity>
      <price>49.9</price>
    </line>
